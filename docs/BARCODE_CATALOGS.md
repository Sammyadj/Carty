# Barcode lookup order

Carty identifies products; shoppers still confirm shelf prices. No catalog
provider price, photograph, ingredient assessment or safety claim is imported.

```text
Validated barcode
  → on-device product cache
  → open-data catalogs (universal Facts API)
      Food / Beauty / Pet Food / Products
  → UPCitemdb Explorer (limited free; only when still unmatched)
  → manual product details if no usable match
```

The [official multi-project API](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/scanning-cosmetics-pet-food-and-other-products/)
supports `product_type=all`, including a redirect to the appropriate catalog.
The response's product type determines the attribution stored with the match.
A documented cosmetic barcode was checked against the live endpoint and returned
a Beauty Facts record. This searches all four catalogs without four speculative
client requests. Unknown product types, mismatched codes and malformed records
are rejected; a match must still be reviewed against the package.

Open data does not mean unlimited traffic. The Facts service's current
[API guidance](https://openfoodfacts.github.io/openfoodfacts-server/api/)
limits product reads per IP. Carty throttles new lookups, deduplicates concurrent
equivalent UPC/EAN requests, caches successful identities and persists server
rate-limit cooldowns. A refresh bypasses a stored product, not a quota/cooldown.

The [UPCitemdb Explorer service](https://devs.upcitemdb.com/) currently permits
100 combined free requests/day without an account or key. Only `/prod/trial`
is enabled. Carty additionally persists a conservative 100-attempt local UTC-day
allowance, ten-second retail spacing and server backoff. Failures still consume
a local attempt. Shared IP/server limits may be reached earlier than this local
allowance; HTTP 429 is respected. Exhaustion never selects a paid endpoint.

## Other services assessed

| Service | Decision |
| --- | --- |
| Open Beauty / Pet Food / Products Facts | Enabled through the open multi-project lookup before quota-limited services |
| UPCitemdb Explorer | Enabled as the final key-free limited fallback |
| [Go-UPC free application](https://go-upc.com/plans/api/trial) | Advertises 150/month with manual approval and an API key; not enabled without the owner's approved free account and a server-held key |
| [upc.dev](https://upc.dev/pricing) | Advertises 100/day free, but its terms require registration/key while docs describe optional public auth; defer until access/terms are clarified and a free key is safely configured |
| [EAN-Search](https://www.ean-search.org/ean-database-api.html) | Excluded: even its API trial currently has a charge and recurring price |

No account, subscription, payment method or billing credential was created.
Keyed fallbacks must be added behind a server adapter, at the limited-free end
of the pipeline; never bundle a provider secret in the app. New services need
verified access, terms, response validation and quota tests before activation.
EAN/UPC/GTIN are barcode formats, not a guaranteed universal free retail catalog.

## Code and persistence

- `barcode_catalogs.dart`: catalog types, tiers and key-free endpoint registry.
- `open_facts_provider.dart`: bounded product-only parsing and multi-catalog attribution.
- `product_lookup.dart`: shared lookup interfaces/results.
- `product_repository.dart`: cache, request deduplication, fallback and quota state.
- `ProductSource`: stable per-catalog source names preserved in list/history/export.

The shared-list validator migration allows these additional source names while
retaining barcode, quantity, price, role and ownership checks. Existing manual,
Food Facts and UPCitemdb records remain readable. Old builds do not recognise
the new source names; use the updated build across household devices rather
than downgrading a workspace containing newer catalog data.

Migration `20261028182927_expand_barcode_catalog_sources` is applied. The file
was generated by the CLI, then aligned with the version recorded by the remote
migration tool. Validator probes and the complete household security fixture
pass inside rolled-back transactions. Post-change advisors match the pre-change
findings: two legacy authenticated definer RPC notices and a password-protection
notice (the app uses email-link sign-in). This change adds no public function or
new grant. See the [function advisor](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)
and [password guidance](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Facts results retain their actual catalog credit and ODbL attribution. UPCitemdb
keeps its own credit/terms. No third-party design references are involved.
